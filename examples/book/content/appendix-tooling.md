# A Note on Tooling

The examples in this book were drafted with nothing more specialized than
plain text files and a version-control habit borrowed from software
teams: every chapter is its own file, and every margin note is a
first-class citizen of the document rather than an afterthought bolted on
in a page-layout tool at the very end.

That ordering matters more than the specific tools. Drafting margin notes
*after* the body is finished tends to produce padding — notes that
restate the paragraph instead of extending it. Drafting them alongside
the body, in the same pass, produces notes that do work: definitions the
paragraph needed anyway, citations the claim actually depends on, asides
the author would otherwise have crossed out.

Three habits carried the most weight across every chapter in this field
guide:

- Write the note before you're sure you need it. Delete it later if the
  paragraph turns out not to need the crutch.
- Keep notes answerable in one glance. If a note needs its own note, it
  was never a note — it was an undrafted paragraph.
- Reread the page, not the note. A note that looks fine in isolation can
  still crowd three neighbors once the column fills in.

None of this requires the specific field-guide structure used here. It
requires treating the margin as part of the draft from the first
sentence, rather than as a place to file exceptions once the "real"
writing is done.
